# Technical Project Explanation

## Overview
This project is designed as a small-scale simulation of a real-world application.
The main focus is on structure, clarity, and correctness rather than complexity.

## Object-Oriented Design
An Expense class is used to represent each expense entry.
This encapsulates all related data into a single object, making the code easier
to maintain and extend.

## Modular Architecture
Each module has a single responsibility:
- expense.py: Defines the Expense object
- file_manager.py: Handles data persistence
- menu.py: Manages user interaction
- reports.py: Performs calculations and analysis
- utils.py: Handles validation and formatting

This separation of concerns follows best practices.

## Data Persistence Using CSV
CSV files are used instead of databases to keep the project simple.
They provide:
- Permanent storage
- Easy debugging
- Compatibility across systems

## Validation and Error Handling
All user inputs are validated before processing.
This prevents invalid data from entering the system and improves reliability.

## Reporting Logic
Reports are generated by iterating over stored expenses and grouping them using
basic data structures like lists and dictionaries.
This demonstrates foundational data analysis skills.
